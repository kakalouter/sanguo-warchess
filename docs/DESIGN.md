玩法系统、全部数值与公式、平衡标定过程。技术实现见 [`DEVELOPMENT.md`](DEVELOPMENT.md)。

## 1. 设计目标与取舍

原始需求里有几条互相拉扯的要求，这里记录取舍依据：

| 需求 | 冲突点 | 取舍 |
|---|---|---|
| 地形与真实中国地理相符 | 青藏高原平均 4500 m，若按真实比例做 3D，它会占据整个画面并把东部压成一条线 | 高程做 `h^0.78` 非线性压缩：低地细节几乎无损，高原被压到不喧宾夺主。地图配色用同一个压缩值，保证颜色与高度一致 |
| 玩起来爽、战斗华丽 | 追求"爽"容易变成无脑推；追求史实还原又容易变成慢节奏经营 | 采用三11 的**战法驱动**路线：每位名将有一击定局的战法（吕布"无双"×2.35），但受士气/天候/兵力限制，不会无限刷 |
| 完整展现主要城池和关隘 | 89 座城池会让邻接图过于密集，失去战略纵深 | 邻接半径标定为 **2.5°**（约 250 km），平均相邻 7.2 城、平均 4.5 跳。第一版用 4.6° 时洛阳到襄平只要 4 跳，等于没有纵深 |
| 能体现兵力后勤 | 后勤做得太细会变成"粮食管理模拟器" | 只保留三条硬约束：出征带 6 倍兵粮、行军每步耗粮、途经己方城自动补给。断粮则逃散，够痛但不烦 |

## 2. 回合与经济

### 2.1 时间
- 一回合 = **一个月**。12 个月后年份 +1。
- 3 月与 9 月为**秋收月**（各结算一次粮产）。

### 2.2 城池类型

| 类型 | 城防基数 | 人口基数 | 粮草基数 | 建筑位 | 说明 |
|---|---|---|---|---|---|
| 都城 capital | 220 | 42000 | 26000 | 8 | 洛阳、长安、许昌、邺、襄阳、江陵、成都、汉中、建业 |
| 郡城 city | 160 | 26000 | 16000 | 6 | 普通州郡治所 |
| 关隘 pass | **300** | 7000 | 5000 | 3 | 虎牢关、潼关、剑阁、雁门关… 城防最高但人口极少 |
| 水寨 port | 170 | 14000 | 9000 | 4 | 濡须口、柴桑、夏口、巴丘 |

城池属性：农业 `agri` / 商业 `comm` / 技术 `tech` / 城防 `def` / 人口 `pop` / 粮草 `food` / 兵力 `troops` / 训练 `train` / 民心 `morale` / 治安 `security` / 民怨 `disorder`。

上限：农业与商业 1600，技术与城防 1200，兵力 200000。

### 2.3 收入公式

```js
// 每月金收入（core.js cityIncome）
治安系数 sec  = 0.55 + security / 100 * 0.55          // 0.55 ~ 1.10
民怨系数 dis  = 1 - min(0.6, disorder / 100)          // 最低 0.4
技术系数      = 1 + tech / 2200
gold = round((comm * 0.62 + pop / 900) * sec * dis * 技术系数)

// 3 月/9 月粮产（cityHarvest）
harvest = round((agri * 1.35 + pop / 160) * dis * (1 + tech / 2600))

// 人口增长（cityGrowth）
room = clamp((cap * 1.6 - pop) / (cap * 1.6), -0.02, 0.5)
增长 = round(pop * (0.006 + room * 0.020) * (1 - min(0.9, disorder/130)) * (0.6 + agri/1500))
```

设计意图：**治安与民怨是两个独立乘数**。疯狂征兵会同时抬高民怨、压低民心，于是收入与产量双降——这就是"穷兵黩武"的代价。

### 2.4 城内耗粮
每月每城消耗 `troops * 0.010 + pop / 900`。不足则 `troops` 损 6%、民心 -8，并产生"粮尽，逃兵 N"的军报。

## 3. 内政指令

每名武将每月**只能行动一次**（`actedThisTurn`），所以"派谁去做"本身就是决策。

| 指令 | 耗金 | 执行者属性 | 效果 |
|---|---|---|---|
| 开垦 | 320 | 政治最高者 | `agri += 14 + pol * 0.42 + rnd(18)` |
| 兴商 | 320 | 政治最高者 | `comm +=` 同上 |
| 技术 | 420 | 智力最高者 | `tech += 14 + intel * 0.42 + rnd(18)`，上限 1200 |
| 修城 | 260 | 统率最高者 | `def += (14 + lead*0.42 + rnd(18)) * 0.7`，治安 +3 |
| 治安 | 180 | 魅力+武力最高者 | `security += 6 + charm*0.10 + war*0.04`，`disorder -= 该值*0.9`，民心 +2 |
| 征兵 | 每兵 0.11 + 0.35 粮 | 魅力最高者 | 见 §3.1 |
| 训练 | 220 | 统率最高者 | `train += 4 + lead * 0.09 + rnd(4)`，上限 100 |
| 登用 | 400 | 魅力最高者 | 见 §3.2 |
| 运输 | — | — | 相邻己方城池间调粮，途中损耗 **8%** |
| 任命 | — | — | 武将调往本势力其他城池 |

### 3.1 征兵公式

```js
人口上限 = floor(pop * 0.055 * (0.4 + security / 160))
可征     = min(人口上限, 200000 - troops)
消耗     = round(n * 0.11) 金 + round(n * 0.35) 粮
副作用   = n / 人口上限                    // 0~1
  pop     -= round(n * 1.7)                // 1 兵吃 1.7 人口
  disorder += 副作用 * 12
  morale   -= 副作用 * 10
```

### 3.2 登用成功率

```js
chance = clamp(0.20 + (说服者魅力 - 目标魅力) / 260 + 说服者智力 / 900
               + 我方金 / 200000, 0.05, 0.9)
```

**在野池只有 130 人**（`_source/roster.js` 的 `REST_SIZE`），且每城限 14 名。第一版把全部 467 名未分配武将都撒进 8 座在野城，导致许昌一城有 60 名在野将（含吕布、甘宁、姜维），400 金就能挖到吕布——完全破坏平衡。现在"某地有贤才"成了地缘理由。

## 4. 军事与后勤

### 4.1 邻接图
关隘连所护城池 → 距离 < **2.5°**（经度按 `*0.95` 修正）互连 → 度数为 0 的城再用 kNN(3) 保底。

实测：平均相邻 **7.2** 城，最少 2，全图 89 城连通，洛阳→襄平 6 跳、敦煌→龙编 13 跳。

### 4.2 出兵
- 最多 **3 名**武将，首位为主将。
- 出征携带 `min(势力总粮, troops * 6)`。
- 部队记录：`troops / food / train / morale / at / path / state`。

### 4.3 行军与断粮

```js
每步消耗 = round(troops * 0.02) + 120
每回合部队自身耗粮（beginTurn）= round(troops * 0.012) + 60
粮 <= 0 → 士卒逃散 28%，士气 -25；兵力 < 300 时整支军团溃散
途经己方城池 → 自动补给 min(城中粮, troops * 3)
抵达敌城 → state = 'sieging'
```

### 4.4 AI 行为（`aiFaction`，每周目对每家势力各跑一次）
1. **内政**：按优先级补短板——缺兵则征兵 → 缺粮则开垦 → 补农业/商业的短板 → 训练 → 修城 → 治安。每城最多 4 个动作。
2. **登用**：金 > 2500 时尝试招募本城最强的在野将（三维和 > 200 才动手）。
3. **军事**：从邻接的**交战**敌城里选战力最低的为target；从最近且兵力 > 8000 的城出兵，派出 `troops * (0.5 + aggression * 0.35)`，带 3 名最强将。
4. **运输**：前线城粮草低于 `troops * 0.5` 时，从相邻的富城调粮。
5. **外交**：战力低于对手 45% 时，有 25% 概率遣使求和（停战 6~11 个月）。

每家势力的 `aggression` 在 0.35~0.75 之间随机，让 AI 有性格差异。

## 5. 战斗数值与公式

### 5.1 兵种

| 兵种 | 射程 | 移动 | 克制 | 被克 | 特点 |
|---|---|---|---|---|---|
| 枪兵 gun | 1 | 4 | 骑 | 弩 | 长枪拒马 |
| 戟兵 hal | 1 | 4 | 枪 | 骑 | 攻守兼备 |
| 弩兵 xbow | **3** | 3 | 枪 | 骑 | 远程，惧近战 |
| 骑兵 ride | 1 | **6** | 弩 | 枪 | 机动最强，山森受阻（森林/山地额外 +1 消耗） |
| 兵器 wep | 2 | 3 | — | 骑 | 攻城特化，非平路额外 +1 消耗 |
| 水军 wat | 2 | 5 | — | — | 唯一能走水面的兵种 |

克制系数：**1.32**（克制）/ **0.78**（被克）。

武将兵种适性 `S/A/B/C` → **1.28 / 1.12 / 1.00 / 0.84**。出兵时自动为每名武将选其适性最高的兵种。

### 5.2 地形

| 地形 | 移动消耗 | 防御加成 | 通行 |
|---|---|---|---|
| 平原 plain | 1 | 0 | — |
| 丘陵 hill | 2 | +12 | — |
| 森林 forest | 2 | +18 | 骑兵额外 +1 |
| 山地 mount | 3 | **+30** | 骑兵不可通行 |
| 峻岭 peak | — | — | 不可通行 |
| 水面 water | — | — | 仅水军 |
| 浅滩 shallow | 2 | −8 | 可通行（水军也走） |
| 城郭 city | 1 | **+45** | — |
| 道路 road | 1 | −5 | 移动最快但无防护 |

**地形的生成方式**：战场 34×24 格，每格从战场高程切片取 2×2 样本求均值，再按该窗口内的**相对高差分位数**判型（`rel > 0.86` 峻岭、`> 0.62` 山地、`> 0.38` 丘陵，另有 16% 概率在低地生成森林）。

> 用分位数而不是固定米数阈值，是为了让**成都平原和青藏高原上的战场都有合理的山丘比例**——否则在高原上每一格都会是"峻岭"，仗没法打。

### 5.3 伤害公式

```js
// 攻方战力
warPart = 用智力时 intel * 1.00，否则 war * 1.05 + lead * 0.30
power   = troops * (0.62 + train/165) * (0.55 + morale/150)
          * (1 + warPart/105) * 兵种适性系数

// 守方战力（结构对称）
defPower = troops * (0.50 + train/175) * (0.55 + morale/165)
           * (1 + (lead*0.75 + war*0.35)/105) * 兵种适性系数

// 修正
counter  = 1.32 克制 / 0.78 被克 / 1.0
atkTerr  = 1 + 攻方地形.def / 300
defTerr  = 1 - 守方地形.def / 190
specMult = 战法威力（1.35 ~ 2.35），智力系再乘天候火势系数

// 命中
acc = clamp(0.66 + (攻方war - 守方lead)/320 + 攻方morale/420, 0.38, 0.96) * 天候命中系数
命中失败 → 伤害 × 0.22

// 伤害（战力差模型）
raw  = power * specMult * counter * atkTerr * defTerr - defPower * 0.80
dmg  = clamp(raw * (0.24 + rnd(0.12)),  troops * 0.020,  守方troops * 0.34)

// 反击（仅当守方射程够且未被"不被反击"战法豁免）
retal = clamp((defPower * 0.42 - atkDef * 0.34) * (0.75 + rnd(0.4)),
              攻方troops * 0.012,  攻方troops * 0.16)
```

**士气打击**：普通攻击 `5 + (兵力占优 ? 3 : 0)`，再乘 `0.7 + rnd(0.7)`；战法用其自身 `morale` 值（8~32），智力系再乘 `0.8 + max(0, 智力差)/170`。

**溃灭判定**：兵力 ≤ 0 即覆灭；`morale ≤ 0` 或 `兵力 < 12% 上限` 时，每回合 55% 概率崩溃退场。

**范围战法**：`aoe` 标记的战法（张飞长坂怒吼、张辽逍遥津、周瑜火烧赤壁、诸葛亮八阵图、陆逊火烧连营、庞统连环计）对目标格相邻 1 格内的其他敌军造成 **34%** 溅射伤害并 −8 士气。

### 5.4 天候

| 天候 | 概率 | 命中 | 火势 | 移动 |
|---|---|---|---|---|
| 晴 | 45% | 1.00 | 1.2 | 1.00 |
| 雨 | 17% | 0.82 | **0（火计完全失效）** | 0.85 |
| 大风 | 13% | 0.86 | 1.7 | 1.00 |
| 雾 | 12% | 0.76 | 0.9 | 0.90 |
| 雪 | 13% | 0.90 | 0.6 | 0.75 |

### 5.5 平衡标定过程（重要）

**初版公式是错的**：单次攻击只打掉 1~8% 兵力、反击几乎与攻击等量，导致双方僵持——自动化测试跑 **60 个半回合仍未分出胜负**（`winner = null`）。

根因是 `dmg = power * M / defPower` 这种比值模型：`power ≈ 12147`、`defPower ≈ 29000` 时，伤害只有 170 左右，而兵力恢复/士气机制让双方谁也压不倒谁。

改为**战力差模型** `(power - defPower * 0.8) * M` 后，经过三轮实测标定：

| 迭代 | 伤害系数 | 单次攻击伤害 | 平均回合数 | 结果 |
|---|---|---|---|---|
| 初版（比值模型） | — | 1~8% | 60+ 未决 | ✗ 僵持 |
| v1 | `0.78 ~ 1.18` | **50.4%** | 9.6 半回合 | 过快，一击半灭 |
| v2 | `0.21 ~ 0.32` | **27.6%** | 15.3 半回合 | 接近可用 |
| **v3（当前）** | `0.24 ~ 0.36` | **29.8%** | **15.9 半回合（约 8 回合）** | ✓ 目标区间 |

同时把反击公式从"几乎与攻击等量"降到 `defPower * 0.42 - atkDef * 0.34` 并夹在攻方兵力的 1.2%~16%——**攻方应该有优势，否则没人愿意进攻**。

> 标定工具：`_test/diag2.html` 会跑 25 场同配置战斗，统计平均伤害、平均回合数、胜负分布。改战斗数值后请重跑，看 §9 的输出段落。

## 6. 武将战法

**36 名**武将有专属战法（写在 `battle.js` 的 `SPECIALS` 表里），其余武将按属性自动分配通用战法：

```js
war >= 90 → 奋勇突击 ×1.60
war >= 82 → 猛攻     ×1.45
intel >= 90 → 火计   ×1.50（智力系，受天候火势影响）
intel >= 82 → 伏兵   ×1.40
lead >= 88 → 鹤翼阵  ×1.40
其余       → 突击    ×1.35
```

战法的四个修饰位：`aoe`（范围溅射）、`noRetal`（不被反击）、`intel`（用智力算威力且受天候影响）、`def`（偏防御）、`ranged`（远程）。
威力上限是吕布的 **2.35**，配合战力差模型可打出 30~40% 的兵力杀伤——这就是"爽"的来源，但受士气 > 45 与 42~50% 的触发概率限制，不会每回合都放。

代表：吕布「无双」、关羽「青龙偃月」、张飞「长坂怒吼」(aoe)、赵云「七进七出」(noRetal)、马超「西凉铁骑」、典韦「古之恶来」(noRetal)、黄忠「百步穿杨」(ranged)、甘宁「锦帆夜袭」、张辽「逍遥津」(aoe)、周瑜「火烧赤壁」(intel+aoe)、诸葛亮「八阵图」(intel+aoe)、司马懿「鹰视狼顾」、贾诩「毒士之计」、陆逊「火烧连营」(intel+aoe)、邓艾「偷渡阴平」、吕蒙「白衣渡江」、高顺「陷阵营」、麴义「先登死士」。

## 7. 剧本与势力

**189 年 · 反董卓联盟**：董卓入洛阳、废少帝立献帝；关东州郡起兵讨之，推袁绍为盟主。

**21 个势力定义**，其中 **17 家可玩**：曹操、刘备、孙坚、袁绍、董卓、刘表、陶谦、孔融、马腾、公孙瓒、袁术、刘焉、张杨、刘繇、王朗、公孙度、士燮。

初始归属按史实分派（86 座城有主，3 座关隘在野）。各家的起始加成见 `data_factions.js` 的 `bonus`：董卓兵甲最盛（金 12000 / 粮 90000 / 兵 90000），刘备最弱（金 1500 / 粮 8000 / 兵 5000）。

**势力配色**：每家一对主色/暗色 + 色相，用于地图领旗、屋顶、部队底座、程序化头像背景。如曹操 `#2f5f8f`（靛青）、刘备 `#b8442a`（朱红）、孙坚 `#a83232`（赤）、袁绍 `#3f6f4a`（苍绿）。

## 8. 胜负与奖励

- **夺城**：攻方全歼守军 → 城池易主，守军残兵的 25% 转为新城守军，粮草打七折，民怨 +30、民心 −25。
- **俘获/招降**：守将每人有 `42% + (忠诚<60 ? 20% : 0)` 概率被俘；被俘者中 `35% + 我方金/200000` 概率归顺，否则下野为在野。UI 会报告"招降 N 人 / 走脱 N 人"。
- **守成**：全歼攻军 → 城池兵力更新为残余守军。
- **败退**：军团兵力 < 400 或战败 → 武将撤回最近的己方城池；无城则可下野。
- **天下一统**：消灭所有敌对势力。**大势已去**：己方城池归零。
- 结算面板会显示：总回合数、攻取城池数、战胜次数、招揽人才数。

## 9. 已调整过的平衡项（改数值前请先读）

| 项 | 初版 | 现在 | 原因 |
|---|---|---|---|
| 城池邻接半径 | 4.6° | **2.5°** | 4.6° 时平均相邻 19.5 城，洛阳→襄平仅 4 跳，无战略纵深 |
| 在野武将总量 | 467 人全撒入 8 城 | **130 人，每城 ≤14** | 否则一城坐拥 60 名在野将（含吕布），400 金挖到顶级武将 |
| 高程映射 | 线性 | **`h^0.78` 压缩** | 线性时青藏高原吞掉整个画面 |
| 单次攻击伤害 | 1~8%（比值模型） | **29.8%（战力差模型）** | 原模型导致战斗永不结束 |

| 地图相机构图 | 取景中心 = 洛阳 | **地图几何中心 + 按视口与俯仰角加权** | 否则地图偏在画面一角 |
| 城池模型缩放 | 固定 | **按相机距离自适应 0.42~1.25** | 远景时 89 座城连成一片糊 |

## 10. 尚未实现 / 可扩展方向

按实现成本从低到高：

1. **战斗动画时序**：目前 AI 回合内单位是"逐个瞬间结算 + 420 ms 间隔"。可加移动补间与攻击前摇。
